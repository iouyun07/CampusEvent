# change-v2 变更影响分析

## 一、变更范围

本次变更实现两条 CR：

- **CR-01 年级限定报名**：新增 `grade_limited` 策略与 `students.grade` 字段；
- **CR-02 模拟邮件通知**：新增 `emails` 表与邮件通知观察者，站内消息保持不变。

不涉及：登录鉴权、前端框架、路由重构、线上重新部署。

## 三、数据与迁移影响

| 对象 | 变更 | 兼容性 |
|---|---|---|
| `students` | 新增 `grade`（默认 1，CHECK 1–4） | `ALTER TABLE ADD COLUMN`，旧行默认大一 |
| `activities` | `policy_type` CHECK 增加 `grade_limited` | SQLite 不支持改 CHECK，迁移时重建表并复制数据 |
| `emails` | 新增表（含 `dedupe_key` 唯一） | 新建，无历史数据 |
| `schema_version` | 新增表 | 记录版本，保证迁移只执行一次 |

迁移路径：启动时 `migrate(conn)` 检测 `students.grade` 是否存在 → 不存在则执行 v1→v2（外键临时关闭、事务内重建 `activities`）→ 写版本 2。空库直接按 `schema.sql` 建 v2，不触发迁移。

回滚方式：迁移在事务内完成，异常自动 ROLLBACK；如需回退代码，旧版本仍可读 v2 库的既有表（多出的列与表不影响 v1 查询），但 `grade_limited` 活动在旧版本中会因 CHECK 失败而无法创建。

## 四、接口与行为影响

- 新增策略值 `grade_limited`，管理端表单可选；直接报名、审核报名行为不变。
- 报名事件新增一个订阅者，站内消息观察者与事件总线本身未改。
- 新增可选配置 `MOCK_EMAIL_FAIL_FOR`（逗号分隔学号），仅用于演示/测试失败分支，默认空。
- 页面新增：策略标签「年级限定」、报名规则后缀「（仅限大二、大三）」、学生切换显示年级。
- 失败语义：邮件发送异常被观察者捕获，业务事务已提交，报名状态不受影响；失败原因写入 `instance/notification_failures.log` 与 `emails.error`。

## 六、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 迁移中断导致半完成 | 库不可用 | 单事务 + 外键临时关闭 + 异常回滚；迁移有专门用例 |
| 邮件重复发送 | 学生收到多封 | `dedupe_key` 唯一 + 先占位再发送，重复事件直接跳过 |
| 年级规则写死 | 未来调整需改代码 | 集中在 `GradeLimitedPolicy.allowed_grades`，一处可改 |
| 观察者异常影响主流程 | 报名失败 | 事件总线与邮件观察者双层捕获，仅记录日志 |
| 线上与本地版本不一致 | 演示混淆 | README 明确线上仍是 baseline-v1，未重新部署 |

## 七、结论

本次变更以「新增类 + 少量接线」完成两条 CR，核心报名/审批流程未改动，baseline 19 条回归全部通过；数据结构变更通过幂等迁移兼容旧库，未采用删库重建。
