## 2. 设计取舍复核

| 取舍 | 复核结论 |
|---|---|
| 年级限定用继承而非独立策略 | 通过：语义上是子集关系，容量逻辑单点维护 |
| 年级由服务注入而非策略查库 | 通过：策略保持无副作用，便于单测 |
| 邮件先占位后发送 | 通过：幂等优先，可审计的「待发送」比重复发送可接受 |
| 不部署 change-v2 | 通过：遵循教师「网站不用改」的要求，README 注明 |

## 3. 评审提出的问题与处理

| # | 问题 | 处理 |
|---|---|---|
| 1 | 年级判断放策略里，是否会让策略依赖学生查询？ | 不查询；`PolicyContext.student` 由服务注入 |
| 2 | 迁移重建 `activities` 时外键引用会不会断？ | 迁移事务内先 `PRAGMA foreign_keys=OFF`，重建后恢复并校验 |
| 3 | 邮件占位后进程崩溃，留下 `待发送` 记录怎么处理？ | 保留为可审计状态，不自动重发；文档记录该取舍 |
| 4 | 重复事件判定是否只看 `registration_id`？ | 用 `email:{type}:{rid}:{status}`，区分「通过」与「拒绝」两类事件 |

## 4. 结论

设计通过评审，可以进入编码阶段。评审遗留（不阻塞）：

- 变更影响分析的量化数据（新增类数、核心类修改数）在实现完成后回填；
- 回归测试表在 27 条测试跑通后补全执行记录。
